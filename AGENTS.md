# AGENTS.md

Runtime instruction set for coding agents working on FlexInsight.
Android fitness app (Kotlin 2.1.20 / AGP 8.13.2 / Compose / Hilt / Room / WorkManager).
Min SDK 26, compile/target SDK 36, JDK 17, Gradle 8.13. Single module: `:app`.

## Commands

```bash
# Build
./gradlew assembleDebug          # debug APK -> app/build/outputs/apk/debug/app-debug.apk
./gradlew assembleRelease        # minified + unsigned: no signingConfig exists in the repo

# Test
./gradlew testDebugUnitTest      # all JVM unit tests (Robolectric)
./gradlew testDebugUnitTest --tests "com.jdluu.flexinsight.domain.calc.VolumeCalculatorTest"
./gradlew testDebugUnitTest --tests "*VolumeCalculatorTest.divides*"   # single method
./gradlew connectedDebugAndroidTest   # instrumented; needs a device/emulator
./gradlew verifyCoverage          # JaCoCo gate: domain >= 95%, data/mapper >= 90% lines

# Lint / analysis
./gradlew lintDebug              # CI lint job; HTML report at app/build/reports/lint-results-debug.html
```

`testDebugUnitTest` triggers `jacocoTestReport` automatically (`finalizedBy` in `app/build.gradle.kts`);
run `verifyCoverage` separately — it is not wired into the test task. AI Trainer (Gemini Nano) cannot
run on emulators; exercise it on a physical device, or use Settings → "Debug AI UI stubs" on debug
builds.

## Boundaries

### Always do
- Run `./gradlew testDebugUnitTest lintDebug` before calling a change done.
- Keep `domain/` and `data/mapper/` at or above their coverage floors — add or update a test in the
  same change whenever logic there moves.
- Inject coroutine dispatchers through `DispatcherProvider` in new and modified code. (Legacy
  direct `Dispatchers.IO` calls remain in `data/ai/GeminiNanoClient.kt`,
  `data/health/HealthConnectRepository.kt`, and `data/preferences/ApiKeyManager.kt` — convert them
  to `DispatcherProvider` if you touch those files; don't add new ones.)
- Use `core.errors.Result` / `ApiError` + `ErrorHandler.handleError(throwable)` for anything that
  crosses a repository or API boundary.
- Prefer `core.logger.AppLogger` (`d`/`i`/`w`/`e`) over `android.util.Log` in new code; it gates on
  `BuildConfig.DEBUG`, so debug logs are stripped from release builds. Several files still call
  `Log` directly — don't add more.
- Bump `FlexDatabase.version` and add a `Migration` when changing Room entities; the schema JSON in
  `app/schemas/` is generated by KSP and is committed — regenerate, never hand-edit.

### Ask first
- Adding or upgrading a dependency in `gradle/libs.versions.toml`.
- Any change to a public API contract: `data/api/` Retrofit interfaces, `data/repository/`
  interfaces, or `domain/model/` types consumed outside their own module.
- Adding a `data/mapper/` rule, since mappers shape what the UI sees and are coverage-gated.
- Bumping `minSdk` / `targetSdk`, or changing ProGuard rules in `app/proguard-rules.pro`.
- Introducing a new Android permission, Health Connect data type, or network host.

### Never do
- Commit `local.properties`, API keys, or real Hevy credentials. The Hevy API key lives in
  encrypted prefs at runtime; test keys belong in fakes only (`app/src/test/.../fakes/`).
- Edit anything under `build/`, `.gradle/`, or `.idea/`, or generated Hilt/Room/KSP output.
- Push to `main` or force-push any branch.
- Add live network calls to unit tests. Tests must run offline and deterministically.
- Rename or move `data.model.**` / `data.api.**` classes without updating `proguard-rules.pro` —
  release builds strip Gson DTO fields and Room/Retrofit break at runtime.
- Claim a change is verified without pasting real Gradle output.

## Project Structure

```
app/src/main/java/com/jdluu/flexinsight/
  domain/            Pure Kotlin. calc/ = stateless calculators (TrainingLoad, Recovery, Volume,
                     Streak, PR, Duration). usecase/ = single-responsibility `suspend operator
                     fun invoke()`. model/ = domain types. No Android imports allowed here.
  data/              Room (local/ + local/dao/), Retrofit (api/), repositories (repository/,
                     split by Query/Mutation/Stats), mappers (DTO<->domain), sync/ (WorkManager
                     + SyncCoordinator behind HevySyncSource), ai/, health/, preferences/, cache/.
  core/              errors/ (Result, ApiError, ErrorHandler), dispatchers/, logger/, network/.
  ui/                Compose screens (dashboard, history, planner, settings, aitrainer,
                     workoutdetail), each with viewmodel/ for state.
  di/                Hilt modules — bindings live here, never in callers.
  widget/            Glance home-screen widget.
app/src/test/        Robolectric + JUnit4 unit tests. fakes/ holds the shared test doubles.
app/src/androidTest/ Instrumented tests (Room migration, Espresso).
app/schemas/         Checked-in Room schema snapshots.
screenshots/         App screenshots embedded in README.md.
```

The visual design system (color, type, spacing, shape, components) is in `DESIGN.md` at the repo
root. Architecture notes and the Hevy endpoint surface are below.

Dependency direction: `ui → domain ← data`, with `di` composing everything and `core` usable from
all three. Hard constraint: `domain/` must contain no `android.*` / `androidx.*` imports. `domain/`
does depend on `data.model` (shared entity/DTO types) and on `data` **interfaces** (`FlexRepository`,
`FlexAIClient`, `HealthConnectRepository`) — never on `*Impl` classes, `data.local`, or `data.api`.

New stat math belongs in `domain/calc/` (pure input→output), not in a repository or a composable.
`FlexRepository` is a facade over narrower Query/Mutation/Stats repository interfaces; bindings for
each live in `di/RepositoryModule.kt`. Sync runs `BackgroundSyncWorker → SyncCoordinator →
HevySyncSource → SyncManager`, which is what lets sync be tested with a fake and no network.
AI goes `FlexAIClient → GeminiNanoClient → ML Kit GenAI` (on-device only), with prompt assembly in
the pure, tested `domain/ai/PromptBuilder.kt`.

### Hevy API surface

Base URL `https://api.hevyapp.com`, `api-key` header. `data/api/FlexApiService.kt` declares exactly
10 endpoints — all GET except `POST /v1/routines`: `workouts`, `workouts/count`,
`workouts/{workoutId}`, `workouts/events`, `exercise_templates`,
`exercise_history/{exerciseTemplateId}`, `routines`, `routines` (POST), `routines/{routineId}`,
`routine_folders`.

Hevy also exposes update endpoints, but none are bound. **The only write the app performs is
`POST /v1/routines`.** `WorkoutMutationRepositoryImpl` sets `needsSync = true` on the local row when
completing/rescheduling a workout, but nothing drains that queue, so the change stays local and the
next pull can overwrite it. Don't assume a workout write round-trips to Hevy.

## Code Style

Official Kotlin style (`kotlin.code.style=official`, 4-space indent). Keep existing local
formatting and trailing-comma style.

Error handling at a boundary:

```kotlin
override suspend fun getWorkout(id: String): Result<Workout> =
    try {
        val dto = apiClient.getWorkout(id, apiKeyManager.getApiKey())
        Result.Success(mapper.toDomain(dto))
    } catch (e: Exception) {
        AppLogger.e("Failed to load workout $id", e, TAG)
        Result.Error(ErrorHandler.handleError(e))
    }
```

ViewModels expose a single immutable `UiState` data class via `MutableStateFlow` + `asStateFlow()`,
annotated `@HiltViewModel` with `@Inject constructor` — never a `var` per field:

```kotlin
private val _uiState = MutableStateFlow(DashboardUiState(loadingState = LoadingState.Loading))
val uiState: StateFlow<DashboardUiState> = _uiState.asStateFlow()
```

Use cases are single-responsibility classes with `suspend operator fun invoke()`. Pure calculators
take inputs and return values — no dispatchers, no clock, no I/O — so they stay unit-testable.
DI bindings go in `di/*Module.kt` with `@Provides @Singleton`; constructor injection elsewhere.

## Testing & Mocking

- Framework: JUnit4 + Robolectric (`@RunWith(RobolectricTestRunner::class)`,
  `@Config(sdk = [28], application = TestApplication::class)`) + kotlinx-coroutines-test,
  MockK, Turbine. Instrumented tests use `androidx.test` + `MigrationTestHelper`, which reads the
  committed `app/schemas/` JSON.
- `TestApplication` isolates `filesDir` per test method; always set it via `@Config` on any test
  touching DataStore or encrypted prefs.
- Test doubles live in `app/src/test/java/com/jdluu/flexinsight/fakes/` (`DomainTestFakes.kt`,
  `VmTestFakes.kt`, `FakeAiClient.kt`); sync fakes sit in `data/sync/SyncTestFakes.kt`. Add a fake
  there rather than mocking an implementation class inline.
- `runTest` + `UnconfinedTestDispatcher`, `Dispatchers.setMain` in `@Before`, `resetMain()` and
  `unmockkAll()` in `@After`. Use `Turbine` for `Flow` and `CompletableDeferred` to time emissions.
- Never hit the Hevy API, Health Connect, or AICore in a unit test. Prefer the fakes; use MockK
  `coEvery` only where a fake would require duplicating a real interface.
- JaCoCo floors are enforced by `verifyCoverage`: `domain` 95%, `data/mapper` 90% line coverage.

## Git Workflow

- Branches: `type/short-slug` — e.g. `refactor/sync-pipeline`, `test/domain-characterization`.
  `main` is the default branch and is protected.
- Commits: Conventional Commits, lowercase, imperative subject under ~72 chars — e.g.
  `feat(ai): add routine-diff prompt section`, `refactor: extract pure PromptBuilder`.

## Done When

A change is complete only when all of the following are true:

1. `./gradlew testDebugUnitTest` exits 0 — including your new tests.
2. `./gradlew verifyCoverage` exits 0 (required for any `domain/` or `data/mapper/` change).
3. `./gradlew lintDebug` exits 0.
4. `./gradlew assembleDebug` exits 0.
5. Room schema JSON in `app/schemas/` is regenerated and committed if entities changed.
6. The summary states what changed, which commands actually ran, and their real exit status.

CI (`.github/workflows/ci.yml`) runs `lintDebug`, `testDebugUnitTest` + `verifyCoverage`, then
`assembleDebug` on JDK 17. Local reproduction of CI is those four commands.
